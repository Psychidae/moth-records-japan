# 15 コミュニティと低費用運営

アカウントを持つ利用者が写真を投稿し、種を集め、競い、交流できるようにする。閲覧は匿名のままとする。運営費は年1,600円程度に抑える。

他の文書と食い違う場合は、この文書を優先する。

## 基本の考え方

1. 閲覧にアカウントを求めない。交流と登録の機能だけログインを求める
2. 投稿は先に公開し、キュレーターが後から直す。管理者の不在で投稿を止めない
3. 確認前の投稿は「未確認」と表示し、分布図の証拠区分を変えない
4. 誤りはいつでも戻せるようにする。すべての操作を履歴に残す
5. 公開サイトの種、地域、文献のページは静的なまま動く。交流の機能が止まっても閲覧できる
6. 認証と決済は既存のサービスを使い、自作しない
7. データが増えて費用がかかるようになったら、運営費の支援から支払う。オーナー個人の負担を増やさない

## 利用者ができること

| 操作 | ログインなし | ログインあり |
|---|---|---|
| 閲覧、検索、CSVの取得 | 可 | 可 |
| 写真、コメント、大会の閲覧 | 可 | 可 |
| 修正提案 | 可 | 可 |
| 写真、記録の投稿 | | 可 |
| コメント、通報 | | 可 |
| マイ図鑑 | | 可 |
| 大会の開催と参加 | | 可 |

ログインしていない訪問者も、公開された写真、コメント、順位を読める。

## ログインと2段階認証

| 項目 | 内容 |
|---|---|
| ログイン方法 | Google、メールのマジックリンク。どちらも Supabase Auth の標準機能を使う |
| パスワード | 保持しない |
| 2段階認証 | Supabase Auth の TOTP。認証アプリの6桁コードを使う |
| キュレーター以上 | 必須。Googleログインでも TOTP を求める |
| 一般の利用者 | 任意で推奨する。最終判断は G13 |
| パスキー | 公式で実験段階なので使わない |

- 判定は JWT の `aal` クレームで行う。キュレーター以上の操作は `app.is_mfa()` で強制する
- Supabase の TOTP に標準の回復コードはない。キュレーター以上には予備の認証アプリの登録を案内する
- 認証アプリを失った場合は、オーナーが本人確認のうえ要素を解除する。手順は `docs/runbook.md` に書く
- メールの無料枠を節約するため、ログイン画面では Google を先に表示する

## 公開プロフィール

`profiles` に次を加える。

| 項目 | 内容 |
|---|---|
| `handle` | 英小文字、数字、下線の3〜20文字。一意。公開の識別子にする |
| `collection_public` | マイ図鑑を公開する。既定は真 |

`display_name` を本名にする必要はないと画面に示す。メールアドレスと UUID は公開しない。

## 写真の公開と非公開

投稿された写真は、産地の情報と生態写真の両面で貴重なので、公開を基本とする。投稿者は写真ごとに非公開を選べる。

`photo_observations` に `visibility` を加える。既定は `public` とする。

| 項目 | `public` | `private` |
|---|---|---|
| ウェブでの表示 | 表示する | 本人の `/me` だけに表示する |
| 地図の写真層 | 表示する | 表示しない |
| マイ図鑑 | 数える | 数える |
| 大会の順位 | 数える | 数えない。他の人が確かめられないため |

- 非公開の写真は公開領域へ移さない
- 非公開から公開へ、公開から非公開へ、本人がいつでも変えられる
- 機微種の出力の規則は `public` にも適用する

## 権限

`reviewer` と `editor` を画面上の「キュレーター」に統合する。`role_assignments` に `curator` を加え、`app.has_role` は `curator` を `reviewer` と `editor` の両方として扱う。既存の関数は書き換えない。

| 画面の名称 | 役割の値 | できること | 任命 |
|---|---|---|---|
| 利用者 | なし | 投稿、コメント、大会、自分の投稿の修正と取り下げ | 登録だけでよい |
| キュレーター | `curator` | 写真と記録の確認と修正、種の移動、文献の管理、学名の変更、コメントと大会の非表示、トップの写真の選定 | オーナーか運営者が単独で任命する |
| 運営者 | `admin` | キュレーターの任命、利用者の凍結、機能の切替、版の公開、固定ページ | オーナーの申請と別オーナーの承認 |
| オーナー | `owner` | 運営者の任命、GitHub、Cloudflare、Supabase の権限 | 別オーナーの承認 |

### 任命の流れ

1. 本人がアカウントを作り、TOTP を登録する
2. 本人がオーナーへハンドル名を連絡する
3. オーナーが `/curate/members` で任命する。招待用のURLは作らない

### 危険な操作の扱い

- 全データの削除、DBの直接操作、HTMLやスクリプトの編集の画面を作らない
- サイトのコードの変更は GitHub の権限を持つ人だけが行う
- キュレーターの変更は `audit_log` に前後の値を残し、`app.undo_curation` で戻せるようにする
- キュレーター1人の移動、却下、非表示は1日200件までとする。超えたら止めてオーナーへ通知する。値は `site_settings` で変えられる
- 自分の投稿を確認済みにできない

### 作業画面

キュレーターの作業は投稿サイトの `/curate` で行う。管理サイトの許可リストへの登録を不要にし、気軽に任命できるようにするためである。`aal2` のセッションだけが使える。

| 画面 | 内容 |
|---|---|
| `/curate` | 未確認の写真と記録、通報の受信箱 |
| `/curate/photos` | 確認、移動、トップの写真の選定 |
| `/curate/records` | 記録の確認と修正 |
| `/curate/taxa` | 学名の変更 |
| `/curate/history` | 変更の履歴と取り消し |
| `/curate/members` | 任命と取消。オーナーと運営者のみ |

`05_portal_admin.md` の W3 と W4 のうち、データの整備はここへ統合する。固定ページ、機能、版の公開は `apps/admin` に残す。

## 投稿の反映

### 写真

機能フラグ `photo_post_moderation` が真のとき、次を満たす写真は検査の完了後に公開する。投稿から公開まで5分以内を目標とする。

- 投稿者の状態が `active` である
- 写真の検査が正常である
- 重複の疑いがない
- `sensitivity` が0である
- 1日の投稿上限を超えていない

満たさないものは従来どおり `pending` として審査へ回す。フラグを切ると全件が審査へ回るので、荒らしが増えたときの緊急停止に使う。

`photo_observations` に `review_state` を加える。

| 値 | 意味 | 表示 |
|---|---|---|
| `unreviewed` | 未確認 | 未確認と表示する |
| `confirmed` | キュレーターが確認した | 表示なし |
| `disputed` | 「別の種では？」の指摘が未解決 | 指摘ありと表示する |

- 投稿者本人には、公開の前から `/me` で自分の写真を見せる
- 未確認の写真は地図の写真層に出すが、発見候補には入れない
- AIを使う場合は、公開を止める方向にだけ働かせる。AIの判定で公開しない
- `process-photo.yml` はアップロードを受けて起動し、完了時に公開領域へ移す

### 記録

投稿された記録は、すぐに「未確認の記録」として種ページの別の欄に表示する。キュレーターの確認後に、地図の証拠区分と記録数へ反映する。`10_automation.md` の「必ず人へ回すもの」は、未確認の欄の表示を妨げない。機微種は確認まで表示しない。

## 読み取りAPI

写真、コメント、順位を数分以内に反映するため、読み取り専用の Worker `apps/api` を置く。`apps/public` に Supabase の依存を入れない規則は変えない。

```text
公開ページ ─ fetch ─> apps/api (Cloudflare Worker, GETのみ, 短時間キャッシュ)
                          │ 公開キーで公開用ビューだけを読む
                          ▼
                      Supabase
```

| URL | 内容 | キャッシュ |
|---|---|---|
| `/v1/featured` | トップの写真 | 10分 |
| `/v1/taxa/<taxon_code>/photos` | 種の写真 | 60秒 |
| `/v1/observations/<code>` | 写真の詳細とコメント | 60秒 |
| `/v1/users/<handle>` | 公開された図鑑 | 5分 |
| `/v1/tournaments` | 開催中の大会 | 60秒 |
| `/v1/tournaments/<code>` | 大会の順位 | 60秒 |

- 書き込みの経路を持たせない。書き込みは投稿サイトから行う
- 秘密鍵を持たせない。Supabase の公開キーと、`anon` に許可した公開用ビューだけを使う
- ビューの中で機微種の出力の規則を適用する。メール、UUID、未公開の投稿を出さない
- 公開サイトの `connect-src` に API のホストを追加する
- API が失敗しても、種ページは静的な内容を表示する。写真は `publish-photos.yml` の毎日の JSON へ切り替える

## マイ図鑑

撮影した種を集め、分類ごとの達成率を表示する。

| 項目 | 内容 |
|---|---|
| 表示する単位 | 科、亜科、族 |
| 属 | 1属1種が多いので表示しない |
| 分母 | その分類に含まれる `status='accepted'` の種 |
| 数える写真 | 本人が投稿し、`published` である写真 |
| 亜種 | 種へまとめて1種と数える |
| 指摘あり | 数えるが、指摘ありと表示する |
| 取込の写真 | 数えない。投稿者が撮影者本人とは確かめられないため |
| 同時投稿の写真 | 数える |

- 結果を保存せず、`photo_observations` からその都度計算する。遅くなった場合だけ集計表を加える
- 種が訂正されたら自動で数え直す
- 既定で `/user/?h=<handle>` に公開する。静的なページ1つが API を読む。本人は `collection_public` を偽にして非公開にできる
- 公開の図鑑には `private` の写真を出さない
- 公開の図鑑では、`sensitivity` 1以上の種を種名なしの件数で表示する

## 大会（ペナントレース）

ログインした利用者なら誰でも、期間と種の範囲を決めて大会を開催できる。運営の承認は要らない。

### 開催の設定

| 項目 | 内容 |
|---|---|
| 大会名 | 60文字まで。文字のみ |
| 説明 | 500文字まで。文字のみ |
| 期間 | 開始日と終了日。最長1年。撮影日がこの範囲の写真を数える |
| 種の範囲 | 下の専用画面で選ぶ |

### 種の範囲の設定画面

キリガのように1つの分類群でないまとまりも扱えるよう、種のリストとして持つ。

- 分類の一覧を開いて、科、亜科、族、属、種のチェックで追加する
- 和名、学名の検索で種を追加する
- 追加した分類の中から、一部の種を除外する
- 対象の種数をその場で表示する
- 過去の大会の範囲を複製できる

### 表

| 表 | 内容 |
|---|---|
| `tournaments` | 永久ID `CP000001`、開催者、大会名、説明、開始日、終了日、状態 |
| `tournament_scope` | 開催者が選んだ分類と、追加か除外か |
| `tournament_taxa` | 開始時に確定した対象の種 |
| `tournament_entries` | 参加者と参加日時 |

| 状態 | 意味 |
|---|---|
| `draft` | 準備中 |
| `open` | 開催中 |
| `ended` | 終了。投稿の受付中 |
| `final` | 結果の確定 |
| `hidden` | キュレーターが非表示にした |

### 順位

- 期間中に撮影した対象の種の数で順位をつける。同数なら先に到達した人を上にする
- 順位表に出るのは参加を押した人だけとする
- `disputed`、`private` の写真と、取込の写真を数えない
- 機微種は `sensitivity` 1以上を対象から自動で除外する。人が希少種の産地へ集まるのを防ぐ
- 撮影日は自己申告である。画面にその旨を書かない。不審な投稿は通報で扱う
- 終了から7日間は投稿を受け付け、14日後に結果を確定する。確定までは訂正で順位が変わる

### 制限

- 開催できる大会は、1人につき同時に3件までとする
- 開始後は種の範囲と期間を変えられない
- 開始前は開催者が取り消せる
- 不適切な大会はキュレーターが `hidden` にする

## コメントと通報

写真ごとにコメント欄を置く。独立した掲示板は作らない。

| 項目 | 内容 |
|---|---|
| 本文 | 1,000文字までの文字のみ。HTML と Markdown を解釈しない |
| URL | リンクにしない |
| 投稿の制限 | 1人1日30件 |
| 編集 | 本人が削除できる。編集はできない |
| 通知 | サイト内の通知のみ。メールを送らない |

`reports` 表で、写真、コメント、大会、プロフィールの通報を受ける。異なる3人が通報すると一時的に非表示にし、キュレーターの受信箱へ入れる。キュレーターの確認で元に戻せる。

## 費用の設計

**段階Bで運営する。** オーナーの決定である。1ドル150円で換算する。

| 段階 | 内容 | 年額の目安 | 状態 |
|---|---|---|---|
| A | 閲覧サイトのみ。`workers.dev` | 0円 | 開始時 |
| B | Cloudflare の独自ドメイン（`.com`）と小規模な投稿 | 約1,600円 | **採用** |
| C | Supabase Pro の本格運用 | 約4.9万円 | 予定なし |

写真の配信には独自ドメインを使う。`r2.dev` は回数の制限があり、本番用ではない。

## データの保管先

| 置き場 | 役割 | 理由 |
|---|---|---|
| Cloudflare R2 | 公開用の画像の配信 | 転送料が無料で、世界中から速く読める |
| ラボのサーバー | 写真とバックアップの控え | 容量を費用なしで確保できる。G15 の後に使う |
| 契約中のウェブサーバー | 当面は使わない | R2 の超過料金が小さいため。容量や規約を確かめてから検討する |

ラボのサーバーは外部からの入口を開けない。ラボ側から定期的に R2 へ取りに行く方式とする。

```text
投稿 ─> R2 ─> 訪問者へ配信
         ▲
         └─ ラボのサーバーが毎日、差分を読み取りで取得する
```

- ラボのサーバーに置く鍵は R2 の読み取り専用とする
- 外部の訪問者はラボのサーバーへ接続しない。サーバーの停止はサイトに影響しない
- 大学や研究室の規定で許可を得てから使う（G15）

### 段階Bの守り方

| サービス | 無料枠 | 守り方 | 超えたときの動き |
|---|---|---|---|
| Cloudflare 静的配信 | 無制限。1版20,000ファイル | ファイル数の検査を続ける | デプロイできない |
| Cloudflare Workers | 1日10万回、CPU 10ms | API の結果をキャッシュする | API が失敗する |
| Supabase Free | DB 500MB、転送量5GB、2プロジェクト | 画像を置かない。API のキャッシュで読み取りを減らす | 書き込みの制限 |
| Cloudflare R2 | 10GB、書き込み100万回、読み取り1,000万回 | 画像の大きさを3種類に絞る | 超過分を課金。1GBあたり月0.015ドル |
| Resend | 1日100通、月3,000通 | Google を勧め、通知はサイト内に出す | ログインメールが届かない |
| Claude API | なし | `ai_triage` を偽のままにする | なし |

- 写真の公開用の画像は長辺2048、800、320pxの3種類とする。実際の平均サイズは PH06 で測る
- 1枚0.5〜1MBと仮定すると、10GBで1〜2万枚が入る
- R2 の使用量が8GB、DBが400MB、メールが1日80通を超えたら、`health-report.yml` が通知する
- バックアップも R2 の10GBに含まれる

### Supabase Free の注意

- 7日間使われないとプロジェクトが停止する。定期処理で防げるかを C10 で確かめる
- 自動バックアップがない。T18 の暗号化バックアップが動くまで投稿を開かない
- 保管庫と写真の複製先である Supabase Storage は無料で1GBしかない。写真の控えはラボのサーバーへ置く。G15 の完了までは控えを持たない

### 段階Cを検討する場合

予定はない。無料枠を超える費用は運営費の支援から支払う。支援で賄えない場合は、投稿の上限を下げて無料枠に収める。

DB が400MBを超えたら、オーナーが支援の残高を見て判断する。移るときは staging を無料の組織へ分ける。同じ組織のままだと月10ドル増える。

## 運営費の支援

フッターに「運営費の支援」のリンクを1つ置く。トップやポップアップで強調しない。

`/support/` に年間の運営費と使い道を示し、外部の決済画面へ移動するボタンを置く。支援はドメイン、保管、サーバーの費用に使う。

| 項目 | 内容 |
|---|---|
| 決済 | Stripe Payment Links。月額なし。手数料はカード3.6%、PayPay 3.98% |
| 本サイトで扱う情報 | なし。カード番号、氏名、メールアドレスを受け取らない |
| 公開サイトの変更 | 外部リンクのみ。スクリプトを読み込まない |

PayPay の個人間送金は使わない。規約で営利目的の送金が制限されている可能性があるためである。

受付の開始前に G14 を確認する。

## 既存サービスとの関係

写真投稿とコメントは、みんなで作る日本産蛾類図鑑の役割と重なる。同図鑑は現在更新を止めているが、掲示板は続いている。コミュニティ機能の一般公開の前に、G2 で運営者へ相談する。

## 受け入れの観点

- ログインなしで写真、コメント、順位を読める。投稿の操作はログインへ案内される
- キュレーターの権限で `aal1` のセッションが拒否される
- 未確認の写真と記録で、地図の証拠区分と記録数が変わらない
- 公開用ビューと API の出力に、メール、UUID、機微種の詳細、未公開の投稿が含まれない
- API を止めても種ページが表示される
- 大会の順位に、不参加者、取込の写真、非公開の写真、機微種、期間外の撮影が含まれない
- 非公開の写真が公開領域、公開用ビュー、API に出ない
- 開始後の大会の範囲を変更できない
- キュレーターの変更を取り消すと、前の値に戻り履歴が残る

## 未確認の点

- Google ログインだけのセッションが `aal1` になることは公式の説明からの推定である。C02 で確かめる
- Stripe の個人登録で表示が必要な情報と、寄付としての扱いは G14 で確かめる
- `.jp` を Cloudflare で登録できるかは未確認である
