# 08 ツール選定と運用耐性

2026-11-06 時点の確認結果。料金と上限は変わるため、T01 の開始時と公開前に再確認する。「確認元」が第三者のものは公式で再確認すること。

## 判断基準

1. 初心者が1人で運用できる。自前サーバーを持たない
2. 使うのをやめても、データと公開サイトを別の場所へ移せる
3. 資金が止まっても公開サイトを残せる
4. 依存を増やさない。標準技術で済むなら専用ツールを入れない

## 選定結果

| 役割 | 採用 | 実装での使い方 | 確認した上限 | 確認元 | 撤退方法 |
|---|---|---|---|---|---|
| 公開サイト配信 | Cloudflare Workers Static Assets | `apps/public/dist` を `wrangler` で配信 | 静的要求は無料で無制限。Free 20,000ファイル、Paid 100,000ファイル、1ファイル25MiB | 公式 | 静的ファイルなので他の配信先へ移すだけ |
| 公開サイト生成 | Astro | `output: 'static'` のみ。Cloudflare 専用アダプタは使わない | 15,628ページを5.5秒で生成（簡略な雛形、手元のMac） | 実測 | 出力はHTML。生成ツールだけ差し替え可能 |
| 投稿、管理画面 | Vite + React | 静的SPAとして配信 | なし | - | 標準的なReact |

## 不採用にしたもの

| 候補 | 理由 |
|---|---|
| Next.js + Vercel | サーバー実行が必要になり攻撃面が増える。本サイトは静的生成で足りる |
| Cloudflare Pages | Workers Static Assets が新規開発の推奨とする第三者情報が多い。静的配信の差はない |
| MapLibre | 都道府県の塗り分けならSVGで足りる。容量の目標300KBに対して負担が大きい |
| exceljs, xlsx | npm の最新版がそれぞれ2023年、2022年で止まっている。変換済みJSONLで不要になった |
| Pagefind | 検索は学名と和名の前方、部分一致が中心で、名前の索引だけで足りる |
| CSSフレームワーク | 長期の更新負担を増やす |
| TaxonWorks の導入 | 記録の管理は優れるが、自前サーバーの運用が必要になる |
| Supabase PITR | $100/月と高い。毎日のバックアップで足りる |
| 有償の外部診断 | オーナーの判断で実施しない |

## 規模の見積もり

JSC の実測（132,584件で展開後約24MB、転送約2.2MB）から換算した試算。

| 記録数 | 全件の転送量 | 最大の県（全体の12%と仮定） | DB概算 |
|---|---|---|---|
| 13万件 | 2.1MB | 2.8MB | 0.2GB |
| 50万件 | 8.2MB | 10.6MB | 0.7GB |
| 100万件 | 16.4MB | 21.2MB | 1.5GB |
| 200万件 | 32.9MB | 42.3MB | 2.9GB |

- DB は200万件でも Pro の8GBに収まる
- 地域ファイルは100万件で25MiBの上限に近づくため、8MiBで分割する
- 全件を1ファイルで配信する方式は50万件あたりで限界になるので採らない

## 費用の見通し

| 段階 | 主な費用 | 月額の目安 |
|---|---|---|
| P0〜P1 閲覧のみ | ドメイン | ほぼ0ドル |
| P2 投稿開始 | Supabase Pro | 25ドル〜 |
| P3 AI開始 | 上に加えてAI | 30〜45ドル |
| 成長時 | Workers Paid 5ドル、Resend Pro 20ドルを必要時に追加 | 55〜70ドル |
| スキャン追加分 | 300GB で R2 約4.5ドル、複製の超過 約4.3ドル | 約9ドル加算 |
| 縮退時 | ドメインのみ | ほぼ0ドル |

AI費用の試算: 修正提案1件を入力6,000、出力1,000トークンとすると約0.044ドル。月100件で約4.4ドル。実測で見直す。安価なモデルへの変更はオーナーの判断で `AI_MODEL` を切り替える。

## 運用上の注意点

| リスク | 内容 | 対策 |
|---|---|---|
| 定期処理の自動停止 | 公開リポジトリは60日間活動がないとスケジュール実行が無効になる | 週次の状態ファイル更新、Healthchecks.io で検知、手順書 |
| Astro の更新頻度 | 2026年1月時点の6系ベータから同年11月に7系へ進んでおり、更新が速い | 版を固定し、更新は年1回まとめて行う。専用機能を使わない |
| Cloudflare への集中 | 配信、保護、バックアップが同じ事業者 | 公開データを GitHub Releases と Zenodo にも置く。スキャンは別事業者へ暗号化して複製する |
| スキャンの消失 | 再スキャンには人手がかかる | 2事業者に保持し、公開可能なものは Zenodo にも置く |
| 権利の申し立て | 公開中のスキャンに異議が来る | 公開停止の仕組みで即時停止する |
| R2 のロック解除 | アカウント管理者なら解除できる | アカウントのMFA、配信用トークンの権限を最小化 |
| Astro の所有者 | 2026年1月に Cloudflare が開発元を買収。MITライセンスは継続と報じられている | 静的出力のみを使うので移行は容易 |
| 無料枠の変更 | どのサービスも条件が変わり得る | 撤退方法を確保し、毎年見直す |
| オーナーへの依存 | 1人だと継続できない | 2人目のオーナー、学会などへの引継ぎ先の検討 |

## 縮退モード

資金や人手が尽きた場合の手順。公開サイトとデータを残すことを優先する。

1. 投稿と修正提案を停止する
2. 最終版の公開データを生成する
3. Zenodo へ全データと公開可能なスキャンを登録する
4. AI と Supabase Pro を解約する
5. 公開サイトは静的ファイルのみで残す

この状態なら、費用はドメイン代のみである。
