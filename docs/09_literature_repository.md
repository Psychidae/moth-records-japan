# 09 文献リポジトリ

蛾類の文献を、次の4つの状態で漏れなく管理する。

| 状態 | 意味 | 利用者に見えるもの |
|---|---|---|
| 外部公開あり | J-STAGE、国会図書館、機関リポジトリなどで読める | 外部へのリンク |
| スキャンあり | 当サイトがスキャンを保持している | 権利方針に応じて閲覧、または所蔵の表示 |
| 発行元が頒布中 | 発行元が有償で提供している | 発行元の入手案内。スキャンは受け付けない |
| 目録のみ | 書誌だけ分かっている | 「スキャン募集中」と投稿の案内 |

どの状態かは、APIの検索結果だけで判断しない。J-STAGE で見つからなくても、発行元が自サイトで公開している場合がある。例えば日本蛾類学会は `蛾類通信` と `Tinea` を自サイトでPDF公開している。**スキャンの募集は、発行元の公開状況を確認したあとに行う。**

## 基本の考え方

1. すでに公開されているPDFには、リンクで到達できるようにする
2. それでも取りこぼしている文献は、権利を持つ人や、保護期間の満了に気づいた人が随時登録する
3. 登録されたPDFを本サイトが保持して公開する

登録できるのは次のいずれかの場合に限る。権利の根拠がないファイルは受け付けない。

| 根拠 | 登録する人 | `rights_basis` |
|---|---|---|
| 自分が著者で、公開の権利を持っている | 著者本人 | `author_self` |
| 著作権の保護期間が満了している | 気づいた人 | `public_domain` |
| CC など公開ライセンスがある | 気づいた人 | `open_license` |
| 発行元の許諾がある | 許諾を得た人 | `publisher_permission` |

## データ構造

`02_schema.sql` の次のテーブルを使う。

| テーブル | 役割 |
|---|---|
| `journals`, `journal_issues` | 雑誌と巻号。収蔵状況の単位 |
| `references_` | 論文などの書誌 |
| `documents` | 本体の所在。外部リンクとスキャンの両方を持つ |
| `document_issues` | ファイルと巻号の対応。1ファイルに複数の号が入る場合がある |
| `document_parts` | ファイルと論文の対応。頁範囲を持つ |
| `rights_policies` | 発行元の一括許諾。任意 |
| `trusted_domains` | 自動公開できるリンク先 |
| `takedown_requests` | 公開停止の申し出 |

1文献に複数の `documents` を持てる。雑誌1号を丸ごとスキャンした場合は、1つの `documents` を複数の論文へ `document_parts` で対応づける。外部PDFでも同様に対応づけ、該当ページがあれば `#page=<番号>` つきのリンクを出す。

## 1. 書誌の自動収集

`harvest-literature.yml` が毎月実行する。人は操作しない。

- 対象は `seed/journals.csv` と、管理画面で追加した雑誌
- J-STAGE: `https://api.jstage.jst.go.jp/searchapi/do?service=3`。雑誌コードで取得する
- NDLサーチ: `https://ndlsearch.ndl.go.jp/api/opensearch`。誌名で取得する。同時に1接続とし、2秒以上の間隔を空ける。継続利用の連絡はゲートG9
- CiNii Research: `CINII_APPID` がある場合のみ使う
- 取得元を `metadata_source` に保存する。提供元のクレジットを `/data/` に表示する

**重複の統合**は次の順で判定する。

1. DOI が同じ
2. 雑誌、巻、号、開始ページが同じ
3. 題名を正規化して一致し、年と第一著者が同じ

3の一致は統合せず、候補として審査へ回す。

## 2. 発行元の公開アーカイブ

学会などが自サイトで公開しているPDFを、一覧ページから取り込む。`seed/archive_sources.json` に発行元を1件追加するだけで対象を増やせる。

`harvest-archives.yml` は次を行う。

1. `robots.txt` を確認し、一覧ページだけを取得する。PDF本体は取得しない
2. リンクの文字（`No.101`, `14巻1号`）と `issue_pattern` から巻号を判定する
3. `http://` のURLは `https://` で応答を確認し、応答すれば `https://` で保存する
4. `documents(kind='external')` と `document_issues` を作る
5. 書誌の巻号と照合し、文献からPDFへリンクする
6. `public_through` より新しい号は `scan_blocked = true` とし、発行元の入手案内を表示する

**確認済みの公開範囲（2026-11-06）**

| 雑誌 | 公開範囲 | ファイル数 | それ以降 |
|---|---|---|---|
| 蛾類通信（ISSN 0286-3537） | No.1〜309 | 234 | 学会が1号900円で頒布 |
| TINEA（ISSN 0493-3168） | 第1巻〜第27巻2号 | 86 | 学会が1号2,000円で頒布 |
| 特別刊行物 | 大部分 | 21 | 一部は頒布 |

PDFの実体は `publ.moth.jp` にあり、`https` でも応答する。一覧ページの更新日は学会のバックナンバー案内より新しいので、一覧ページの記載を優先する。1ファイルに複数の号が入る場合（`jhs4-11.pdf` など）は `document_issues` で全号に対応づける。

**発行元が頒布中の号は `scan_blocked` にし、スキャンを受け付けない。** 公開範囲が広がったら月次の取込で自動的に解除する。

## 3. 公開コピーの探索

`find-copies.yml` が毎週、本体のない文献を処理する。

1. DOI があれば `https://api.openalex.org/works/doi:<DOI>` の `open_access.oa_url` を確認する
2. J-STAGE は書誌のURLを使う
3. NDLサーチの応答に含まれるデジタルコレクションのURLを確認する
4. BHL は APIキーがある場合のみ検索する

見つけたURLは `documents(kind='external')` に登録する。`trusted_domains` に一致すれば自動公開し、それ以外は審査へ回す。

OpenAlex の応答はJaLCのDOIで取得できない場合があった（`10.20848/kontyu.13.1_13`）。取得できなくても処理を続ける。OpenAlex と CiNii の利用条件は L01 の開始時に確認する。

## 4. 収蔵状況の公開

`/library/<journal>/` に巻号の表を出す。

```text
（架空の例）○○蛾類同好会報
巻号   年     状態           論文数
1      1970   スキャンあり     8
2      1971   目録のみ         6   [スキャンを提供する]
3      2024   発行元が頒布中   5   [入手方法を見る]
```

利用者は巻号を担当として予約できる（`claimed_by`、30日で自動解除）。同じ号の二重スキャンを防ぐ。

## 5. PDFの登録

機能フラグ `scan_uploads_open` が真のときのみ受け付ける。

1. ログイン利用者が `/upload` で雑誌と巻号を選ぶ
2. 権利の根拠を選び、申告する（`rights_basis`, `uploader_declaration`）
   - `author_self`: 著者本人であること、共著者の同意があること、雑誌へ権利を譲渡していないことを確認する
   - `public_domain`: 著者の没年、団体名義なら公表年と、その出典を入力する
   - `open_license`: ライセンスと確認先のURLを入力する
   - `publisher_permission`: 許諾の内容を入力する
3. Edge Function `upload-start` が検証し、隔離バケットへの署名URLを発行する。同じ文献がすでに公開されている場合と、`scan_blocked` の号は受け付けない
4. ブラウザから R2 へ直接アップロードする

**制限**

| 項目 | 値 |
|---|---|
| 形式 | PDF, TIFF, JPEG, PNG |
| 1ファイル | 500MB まで |
| 1利用者 | `trust_level` 0: 1日1GB、1: 1日5GB、2: 1日20GB |
| 署名URLの有効期限 | 15分 |

署名URLではサイズを制限できないため、処理の最初に実サイズを確認し、超過分は削除する。署名URLはログに出さない。

## 6. 検査と再生成

`process-scan.yml` がすべて自動で処理する。

**処理は2段階に分ける。**

**段階1 隔離処理（信頼しない）**

- GitHub Actions の使い捨て実行環境で動く
- 持たせる鍵は隔離バケットの読み取りのみ。本番DBの鍵を持たせない
- 処理はコンテナ内で `--network none` で実行する

1. 実サイズとファイルの先頭バイトを確認する
2. 元ファイルの SHA-256 を計算する
3. ClamAV で検査する。検出時は `malware_result='infected'` とし、ファイルを削除する
4. OCRmyPDF を `--force-ocr` で実行し、全ページを画像から再生成して文字層を付ける。言語は `jpn+jpn_vert+eng`
5. 再生成したファイルから JavaScript、埋め込みファイル、外部リンクがなくなったことを確認する

**段階2 登録（信頼する）**

段階1の成果物だけを受け取り、次を行う。

1. `stored_sha256` で重複を確認する
2. 非公開バケットへ保存する
3. `documents` を更新する。元ファイルは隔離バケットから削除する
4. 書誌との対応づけ（`document_parts`）を作る。目次の文字と書誌の題名、ページ番号を照合し、`confidence='auto'` とする
5. `status` を `awaiting_review` にし、公開判定へ進む

隔離バケットは7日で自動削除する。OCRの結果は検索用に保持するが、公開サイトに全文を出さない。

実際に使える OCRmyPDF の引数と、縦書きの精度は L05 で実文献を使って確認し `docs/decisions.md` に記録する。

## 7. 権利の扱い

権利は文書ごとに登録者が申告する。公開判定は次の順に行う。

| 申告 | 自動公開の条件（`auto_publish_declared_scans` が真のとき） | それ以外 |
|---|---|---|
| `public_domain` | 基準年が1967年以前、出典あり、登録者の `trust_level` が1以上 | 審査者が1回確認 |
| `author_self` | 登録者の氏名が `reference_authors` と一致し、`trust_level` が1以上 | 審査者が1回確認 |
| `open_license` | 確認先が `trusted_domains` にある | 審査者が1回確認 |
| `publisher_permission` | なし | 審査者が1回確認 |

共通の条件は、検査が正常であること、`scan_blocked` でないこと。公開範囲の既定は `open`。

**保護期間の基準**: 文化庁の資料では、保護期間は著者の死後70年、団体名義は公表後70年で、2018年12月29日時点で消滅していた権利は復活しない。このため、没年または団体名義の公表年が1967年以前を満了候補とする。複数の著者がいる場合は最後に亡くなった著者の没年を使う。戦時加算など例外があるので、画面で注意を表示する。

**著者本人の確認**: 申告と氏名の照合のみとし、本人確認書類は求めない。ORCID があれば表示する。誤りは公開停止の仕組みで対応する。

**発行元の一括許諾（任意）**: 学会などから雑誌全体の許諾を得た場合は `rights_policies` に登録し、1件ごとの申告を省略できる。権利方針の申請者と承認者は別の人とする。

| `access_level` | 意味 | 配信 |
|---|---|---|
| `open` | 誰でも閲覧。既定 | 公開バケット、`files.<domain>` |
| `registered` | ログイン利用者のみ閲覧 | 非公開バケット、5分有効の署名URL |
| `metadata_only` | 所蔵の表示のみ | 配信しない |

利用規約に、登録者が申告の正確さに責任を持つこと、問題があれば公開を止めることを明記する。規約の文面は公開前に専門家または学会へ確認する。この節は実装仕様であり法的助言ではない。

## 8. 配信の防御

- 公開バケットは `files.<domain>` のカスタムドメインで配信する。本体サイトとドメインを分ける
- 全ファイルに `Content-Security-Policy: sandbox`, `X-Content-Type-Options: nosniff` を付ける
- バケットごとに別のAPI鍵を使う。Web側に保存の鍵を置かない
- `robots.txt` で `files.` のクロールを止める

## 9. 公開停止

`/takedown/` で誰でも申し出できる。

1. 申し出を受けると Edge Function `takedown-create` が該当文書の `status` を `takedown` にし、公開バケットから非公開バケットへ移す
2. 管理者へ即時通知する
3. 管理者が内容を確認し、継続か取り下げを決める

権利者の保護を優先し、確認前でも配信を止める。不当な申し出は確認後に戻せる。回数制限と Turnstile を付ける。

## 10. 保全

スキャンは作り直すのに人手がかかるので、提供元を分けて保持する。

| 複製 | 方法 | 頻度 |
|---|---|---|
| Cloudflare R2 | 正本 | - |
| Supabase Storage | `age` で暗号化して複製 | 毎週 |
| Zenodo | `open` のスキャンを巻単位で登録 | 巻の完了時に自動 |

`replicate-archive.yml` は SHA-256 の一覧を比較し、差分だけを送る。毎月、無作為に10件を別サービスから取り出して検証する。

## 容量の見積もり

| 号数 | 1号30MBの場合 | R2 の費用 |
|---|---|---|
| 2,000号 | 60GB | 約1ドル/月 |
| 10,000号 | 300GB | 約4.5ドル/月 |
| 30,000号 | 900GB | 約13.5ドル/月 |

R2 のバケット容量は無制限で、配信の転送料金はかからない。OCRの再生成でサイズが増える場合があるので、L05 で実測する。
